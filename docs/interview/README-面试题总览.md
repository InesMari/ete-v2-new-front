## 二点五、每道题的三个区块（怎么用）

每道题都由三个区块组成，对应备考的三个阶段：

| 区块 | 形式 | 用途 |
|---|---|---|
| **详细回答（口述稿）** | 一段完整、流畅的第一人称话术（可直接照着说） | 把答案要点串成一段能"说出口"的回答，含知识串联 + 项目案例引出 |
| **答案要点** | 分点 bullet | 记忆提纲，考前快速过一遍 |
| **【项目案例】** | 真实源码/业务场景 | 需要展开讲深度的"弹药库"，被追问时用 |

**备考建议**：先背「答案要点」形成骨架 → 再读「详细回答」学会怎么把骨架串成话术 → 最后用「项目案例」应对追问。面试时不要背稿，把口述稿的"起承转合"（先结论、再分层、后举例、收尾总结）变成自己的表达习惯。

## 四、备考建议（按你的背景）

1. **简历是面试的剧本**：简历中每一条（SaaS 架构、组件库、12 个小程序、AI 落地）都可能被追问，04 篇 20 题逐条覆盖，先按顺序自述一遍。
2. **原理题要能"画图讲"**：02 篇的响应式、diff、事件循环，建议在白板上画图（数据流/渲染树），能画出来基本就稳了。

5. **手写题练习**：防抖节流、深拷贝、Promise、发布订阅，01/02 篇的答案含可直接背诵的代码实现。
6. **简历埋点优先补 06 篇**：简历写了"精通 HTML5/CSS3、Less/Sass、rem 适配"，06 篇 11 题就是为这些埋点准备的——BFC、层叠上下文、flex、垂直居中、移动端适配原理（dpr/1px）先背熟，别让"精通"两个字被追问穿帮。

## 五、答题心法

- **STAR 法则**：讲项目经历用 Situation（背景）→ Task（任务）→ Action（行动）→ Result（结果）。
- **"5W2H"展开**：任何技术方案，都要能回答 What（是什么）Why（为什么）How（怎么做）+ 取舍。
- **先结论后展开**：面试官时间有限，先一句话给结论，再分层展开细节。
- **主动带节奏**：答完一个点，顺势说"这在我们的项目里是这样落地的"，把面试官引向你有准备的深水区。
